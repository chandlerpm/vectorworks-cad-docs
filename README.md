# Vectorworks CAD Documentation Sample

Real procedural documentation, written on the job for a working design team, de-identified for public portfolio use.

## What this is

Two internal guides I wrote for a small architecture firm's CAD team, covering their Vectorworks project-sharing setup and day-to-day drawing standards. This isn't a demo project built to look like documentation — it's the actual documentation a team used, with the firm name, server addresses, client names, and other identifying details replaced by placeholders or redacted. The procedures, structure, and screenshots are otherwise unchanged.

## Contents

- **[Vectorworks Technical Guide](docs/vectorworks-technical-guide.md)** — day-to-day drawing standards: title blocks, sheet setup, symbols, sections, and the automated conventions that keep a multi-person CAD project consistent.
- **[Project Sharing & Version Control Concepts](docs/project-sharing-workflow.md)** — onboarding material explaining a checkout/commit workflow (Vectorworks' answer to version control) to a design team with no prior source-control background.

## Why these two

Together they show two different documentation problems:

- The **Technical Guide** is reference documentation — dense, procedural, organized for scanning and lookup, with warnings called out where a wrong click has real consequences (e.g. converting a title block "Unstyled" breaks it project-wide).
- The **Concepts guide** is a conceptual explainer — translating an unfamiliar workflow (checkout, commit, working files vs. server files) into language a non-technical audience already understands, using a library-checkout analogy instead of source-control jargon.

## A note on the de-identification

The original documents included the firm's real name, an internal server address, and a Resource Manager full of real client project names visible in file-browser screenshots. Rather than build a synthetic "fake" documentation sample from scratch, I opted to redact and replace the identifying content directly in the original screenshots and text — same layout, same real workflow, no fabricated content standing in for real work.
